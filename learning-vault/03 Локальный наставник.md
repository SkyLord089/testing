# Локальный наставник — обновлённая настройка под LearnHarness

## Компьютер и цель
Ryzen 7 5700X (8 ядер / 16 потоков), 16 ГБ DDR4, Windows 11, RX 580 (4 или 8 ГБ VRAM — уточняется). Цель — локальный текстовый наставник в связке с LearnHarness без LM Studio и лишних оболочек. Реальные скорости на этом ПК нужно замерить по месту.

## Что важно знать про устройство LearnHarness (по коду v0.6.1)
1. **Большой системный промпт + инструменты.** Сессия Teach состоит из двух фаз: сначала `Prober` уточняет уровень через карточки вопросов и вызывает `probe_done`, затем включается `Teacher` (`plan_init`, вопросы, разбор, чтение учебных файлов `read`/`ls`/`find`/`grep`). Промпт `Teacher` (~40 КБ текста) вместе со схемами ~12 инструментов занимает **около 12 000–15 000 токенов ещё до истории диалога**. Поэтому контекст `4096` или дефолтный `8192` мал: начинать стоит с **`-c 24576` (24K)** (минимум `16384` при жёсткой нехватке памяти) и указывать то же число в пине `Context budget` внутри LearnHarness.
2. **Фоновое построение графа конкурирует с уроком.** По умолчанию после ~4096 токенов объяснений LearnHarness запускает фоновых субагентов извлечения графа знаний. На одном локальном сервере это создаёт очередь и вытесняет кэш промпта урока. На старте лучше отключить автоматическое извлечение графа в настройках LearnHarness и запускать `llama-server` с `--parallel 1` и `--cache-ram 2048` (вместо дефолтных 8192 МБ у `llama-server`).
3. **Строгий протокол инструментов.** Маленькой модели приходится одновременно держать русский язык поверх англоязычного системного промпта и аккуратно вызывать JSON-инструменты карточек вопросов. В первом сообщении сессии явно просить вести урок и вопросы строго на русском языке.

## Движок: прямой llama.cpp (`llama-server.exe`)
Официальные сборки Windows x64: https://github.com/ggml-org/llama.cpp/releases
- Для проверки RX 580: `llama-b...-bin-win-vulkan-x64.zip` (Polaris не поддерживается актуальным ROCm, CUDA — только NVIDIA; на Windows для RX 580 нужен именно Vulkan и свежий релиз осени 2026+, где исправлены ранние ошибки Vulkan на Gated DeltaNet и парсер Gemma 4).
- Для чистого эталона процессора: `llama-b...-bin-win-cpu-x64.zip` (или флаг `-ngl 0`).

## Кандидаты моделей (ноябрь 2026)
1. **Основной старт — `Qwen3.5-4B` (`Q4_K_M`, ~2.74 ГБ):**
   https://huggingface.co/unsloth/Qwen3.5-4B-GGUF/blob/main/Qwen3.5-4B-Q4_K_M.gguf
   У младших моделей Qwen3.5 (0.8B–9B) режим длинных размышлений (`thinking`) по умолчанию выключен в шаблоне — модель не тратит тысячи лишних токенов перед каждым вызовом инструмента. Гибридная архитектура (Gated DeltaNet + внимание) экономно расходует память под контекст 24K.
2. **Более умный кандидат — `Qwen3.5-9B` (`Q4_K_M`, ~5.68 ГБ):**
   https://huggingface.co/unsloth/Qwen3.5-9B-GGUF/blob/main/Qwen3.5-9B-Q4_K_M.gguf
   Проверять, если 4B путается в инструментах LearnHarness. Подходит для RX 580 на 8 ГБ или CPU при свободной RAM; в 4 ГБ VRAM целиком не поместится.
3. **Альтернатива без Gated DeltaNet — `Gemma 4 E2B IT` (~3.11 ГБ) / `Gemma 4 E4B IT` (~4.98 ГБ) в `Q4_K_M`:**
   https://huggingface.co/unsloth/gemma-4-E2B-it-GGUF/tree/main
   https://huggingface.co/unsloth/gemma-4-E4B-it-GGUF/blob/main/gemma-4-E4B-it-Q4_K_M.gguf
   Обучены на специальных токенах вызова инструментов; классический трансформер (полезно, если драйвер Vulkan на RX 580 даст сбой на гибридных слоях Qwen3.5). Сравнивать качество русского языка и разбора кода.

*(В ветке Qwen3.8 моделей на 4B/8B нет — младшая там 27B, для 16 ГБ RAM она слишком тяжёлая.)*

## Команды первого запуска
Папка движка `C:\AI\llama-vulkan`, папка моделей `C:\AI\models`.

Проверка видимости видеокарты:
```powershell
.\llama-server.exe --list-devices
```

Запуск на RX 580 через Vulkan:
```powershell
.\llama-server.exe -m "C:\AI\models\Qwen3.5-4B-Q4_K_M.gguf" --alias qwen35-4b -c 24576 --parallel 1 --cache-ram 2048 -ctk q8_0 -ctv q8_0 -ngl 99 --jinja --host 127.0.0.1 --port 8080
```
*(На RX 580 4 ГБ при нехватке VRAM снизить `-c` до `16384` или уменьшить `-ngl`, например `-ngl 24`.)*

Эталонный запуск на CPU Ryzen 7 5700X:
```powershell
.\llama-server.exe -m "C:\AI\models\Qwen3.5-4B-Q4_K_M.gguf" --alias qwen35-4b -c 24576 --parallel 1 --cache-ram 2048 -ctk q8_0 -ctv q8_0 -ngl 0 -t 8 -tb 14 --jinja --host 127.0.0.1 --port 8080
```

Не включать встроенные серверные инструменты самого `llama-server` (`--tools`) — инструменты урока выполняет LearnHarness через стандартные OpenAI tool calls.

## Подключение в LearnHarness
1. Установить релиз с https://github.com/amosblomqvist/learnharness/releases (`LearnHarness-...-x64-setup.exe`, инсталлятор под Windows не подписан).
2. `Settings → Providers → + Add a provider → Custom endpoint`:
   - Base URL: `http://127.0.0.1:8080/v1`
   - Authentication: `Keyless` → `Connect`
3. В переопределениях (pins) модели `qwen35-4b` выставить:
   - `Context budget`: `24576` (согласовать с `-c` на сервере)
   - `Maximum output`: `2048` (или `4096`)
   - `Reasoning`: выкл. на первом тесте
4. Поставить `qwen35-4b` в `Strong` и `Cheap`. Изображения пока не подавать.
5. Отключить автоматическое фоновое извлечение графа на время живых занятий.

## Приёмочный тест (5–10 минут)
1. Начать сессию Teach: попросить разобрать указатели и ссылки в C++ строго на русском языке.
2. Убедиться, что `Prober` присылает интерактивную карточку вопроса, а после ответов вызывает `probe_done` и `Teacher` строит план урока (`plan_init`) без ошибки переполнения контекста.
3. Посмотреть в консоль `llama-server`: первый запрос обрабатывает большой системный промпт дольше всего, со второго шага должен срабатывать кэш префикса, ускоряя отклик.
4. Проверить короткую задачу с ошибкой в коде C++ и чтение безопасного тестового `.txt` из отдельной учебной папки.
