# Как это вообще работает (и почему «из коробки» не взлетает)

## Цепочка вызовов под нагрузкой

```
ComfyUI (Python)
  └─ PyTorch 2.7.0+cu118        ← CUDA-сборка, тянет cublas64_11.dll / cusparse64_11.dll / nvrtc64_*.dll из torch\lib
       └─ ZLUDA                 ← подменные cublas/cusparse/nvrtc/nvcuda (rocm6 для HIP 6.x)
            └─ HIP runtime      ← amdhip64.dll (HIP SDK, рекомендуемая 6.2.4; 6.4 — тупик)
                 └─ rocBLAS     ← GEMM-ядра; ванильный из HIP SDK НЕ содержит gfx803 → подменяем патчем (собран под 6.2.4/5.7.1)
                      └─ AMD драйвер (Adrenalin) + железо RX 580 (gfx803, Polaris)
```

Ключевой момент: PyTorch+cu118 «не знает», что работает на AMD. Он честно вызывает CUDA API,
ZLUDA перехватывает эти вызовы и переадресует их в HIP, а HIP исполняет на Polaris через драйвер.

## Почему официальный HIP SDK не видит RX 580

`gfx803` был снят с официальной поддержки ROCm задолго до ветки 6.x. В HIP SDK 6.2.4 и 6.4
`rocblas/library` не содержит Tensile-ядер для `gfx803`, поэтому первый же большой GEMM
падает с ошибкой «no binary for GPU» / `hipErrorNoBinaryForGpu` / молчаливым крашем.
Патч advanced-lvl-up кладёт туда пересобранные Tensile-библиотеки для gfx803 (готовый архив
собран под HIP SDK 5.7.1 и 6.2.4; на 6.4 НЕ работает — сборка не экспортирует rocblas_*_64, требуемые
hipblas.dll 6.4, `import torch` падает с WinError 127; на 6.2.4 — обкатанный путь).

## Почему torch нужен именно CUDA-сборки

У AMD под Windows нет поддерживаемой нативной сборки PyTorch под gfx803:

- официальные ROCm-чи-колесики PyTorch (rocm6.x) — Linux only;
- TheRock (новый официальный путь AMD для Windows) — архитектуры от gfx900+/RDNA и новее, не Polaris;
- неофициальные «jammm»-сборки — для GCN4/Polaris не выпускались в полноценном виде на torch 2.7;
- поэтому единственный рабочий путь на Windows 11 для RX 580 сегодня — **ZLUDA**.

`cu118` выбран потому, что именно CUDA 11.8 + ZLUDA (ветка rocm5/rocm6) обкатана сообществом на Polaris
(ComfyUI-Zluda пинует torch 2.2.1+cu118; вы просили 2.7.0+cu118 — см. раздел ниже).

## Почему именно ZLUDA v3.9.5

- v3.9.5 (тег `rel.5e717459179dc272b7d7d23391f0fad66c7459cf`) — последний релиз, в котором есть обе сборки:
  `ZLUDA-windows-rocm5-amd64.zip` и `ZLUDA-windows-rocm6-amd64.zip`.
- В v3.9.6 сборка `rocm6` исчезла, остался только `windows-amd64` и `windows-rocm5`.
- Для HIP SDK 6.x по инструкции advanced-lvl-up берём `rocm6`-сборку ZLUDA, а `nvcuda.dll` внутри неё
  заменяем на `nvcuda.dll` из `rocm5`-сборки (так устроен обход проблемы с драйвером gfx803).

## Что такое «патч DLL torch» и зачем он

Официально ZLUDA распространяется как набор DLL (`cublas.dll`, `cusparse.dll`, `cublasLt.dll`, `nvrtc.dll`, `nvcuda.dll`).
PyTorch при этом грузит **свои** копии этих библиотек из `torch\lib` по точным именам
(`cublas64_11.dll`, `cusparse64_11.dll`, …). Поэтому мы:

1. бэкапим оригиналы (`*.orig`),
2. кладём поверх них ZLUDA-версии под теми же именами.

После этого `import torch; torch.cuda.is_available()` под `zluda.exe` вернёт `True` и покажет вашу RX 580.

## Первый запуск и кэш

ZLUDA компилирует PTX→GCN на лету. Первый прогон (и почти каждый первый прогон с новыми настройками/разрешением/семплером)
может занимать **10–30 минут**, при этом GPU может выглядеть «почти простаивающим», а в консоли мелькать
`Compilation is in progress`. Это нормально. Для индикации поставьте `ZLUDA_COMGR_LOG_LEVEL=1`.
Дальше — быстро, из кэша.

## Известные грабли gfx803

- **VRAM 8 ГБ**: SD 1.5 — норма; SDXL — только lowvram/GGUF; FLUX — только GGUF Q2–Q4, ширина ≤ 768, и то на грани.
- **fp16** на Polaris ускоренный — включайте `--force-fp16`.
- **VAE-декод** иногда «съедает» системную память → артефакты/краши. Лечится `--cpu-vae`, `--fp32-vae`,
  tiled VAE или TinyVAE.
- **Above 4G Decoding / MMIO**: редкие платы с модом RX 580 2048SP 16 ГБ требуют включённого above-4G/resizable BAR в BIOS.
- **Слабое питание/кулер**: Polaris охотно «дросселит». Под нагрузкой compute-задачами карта греется сильнее обычного;
  при нестабильности — даунвольт/андерклок в WattMan.
- **2048SP vs 2304SP**: все механизмы одинаковы.
