# zluda_rx580 — PyTorch 2.7 + ZLUDA на AMD RX 480 / 570 / 580

Набор для запуска ComfyUI через ZLUDA на картах Polaris (gfx803) с HIP SDK 5.7.

**Главное:** причина, по которой всё ломается начиная с PyTorch 2.3, найдена и
прослежена по исходникам до конкретной строки. Это не «мало видеопамяти».
Подробности — в [docs/ROOT_CAUSE.md](docs/ROOT_CAUSE.md).

> ⚠️ **Честно о проверках.** Ничего из этого не запускалось на реальной RX 580:
> в распоряжении была только Linux-машина без GPU и без Windows. Цепочка причин
> выведена чтением исходников PyTorch, ZLUDA и ROCm/clr и подтверждена одним
> сторонним логом с RX 580. Код набора покрыт тестами, которые реально
> выполнялись (см. раздел «Тесты»), но поведение на видеокарте нужно подтвердить
> у вас — для этого есть `run_diagnose.bat`.

---

## Коротко о причине

PyTorch 2.3.0 (PR #119202, коммит `579999a7313c`) перевёл `.item()` на выделение
**pinned-памяти**. Под ZLUDA это `cudaHostAlloc` → `hipHostMalloc(..., flags=0)`,
который на gfx803 запрашивает SVM с атомарными операциями. Windows-бэкенд PAL
включает эту возможность только для GfxIp9 и новее, RX 580 — это GfxIp8, поэтому
выделение всегда возвращает `hipErrorOutOfMemory` (= 2 = `CUDA_ERROR_OUT_OF_MEMORY`).

Отсюда и сообщение, которое выглядит как нехватка памяти, хотя памяти хватает:

```
CUDA error: out of memory
```

PyTorch 2.2.1 работал, потому что в нём `.item()` копировал значение в обычную
переменную на стеке — без pinned-памяти.

## Установка

Нужен только Windows 10/11 и Python 3.10+ в PATH (рекомендуются 3.11 и 3.12).
`git` не обязателен — без него ComfyUI скачается архивом через `curl` и `tar`.

Скачайте этот каталог в любое место, например `D:\zluda-rx580\`, и запустите:

```bat
install_comfyui.bat
```

Скрипт делает всё сам и **идемпотентен** — повторный запуск обновит ComfyUI и
доустановит недостающее, не ломая уже поставленное.

### Что произойдёт

| шаг | действие |
|---|---|
| 1 | проверка `python.exe` и версии (ComfyUI требует `>=3.10`, `pyproject.toml`) |
| 2 | ComfyUI: `git clone --depth 1`, а без git — архив с `codeload.github.com` |
| 3 | виртуальное окружение `venv` |
| 4 | PyTorch 2.7.1 +cu118 (откат на 2.7.0) и `requirements.txt` ComfyUI |
| 5 | ZLUDA v3.9.5 rocm5 и подмена `cublas64_11.dll` / `cusparse64_11.dll` / `nvrtc64_112_0.dll` |
| 6 | автоактивация набора через `.pth` |

После установки:

```
D:\zluda-rx580\
├── ComfyUI\               <- скачанный ComfyUI, модели кладутся в models\
├── venv\                  <- окружение с torch 2.7 +cu118
├── zluda\                 <- ZLUDA v3.9.5 rocm5
├── zluda_rx580\           <- пакет
├── tests\
├── install_comfyui.bat
├── run_diagnose.bat
└── run_comfyui.bat
```

### Если ComfyUI у вас уже есть

Скопируйте содержимое этого каталога **внутрь** папки ComfyUI (рядом с
`main.py`) и запустите `install_comfyui.bat` там. Скрипт увидит `main.py`,
ничего скачивать не будет и не станет трогать ваш git — только поставит
окружение и PyTorch.

### Проверить и запустить

```bat
run_diagnose.bat              :: диагностика
run_comfyui.bat               :: запуск
run_comfyui.bat venv-torch27  :: другое окружение, если оно есть
```

Первый запуск компилирует ядра ZLUDA — от 10 до 40 минут. Это нормально.

### Подтвердить диагноз (на старом torch 2.2.1)

Если у вас ещё работает сборка с torch 2.2.1, запустите диагностику в её
окружении — это подтверждает диагноз за одну команду:

```bat
run_diagnose.bat venv-old --check pin
```

Если диагноз верен, проверка **упадёт** с `CUDA error: out of memory` — даже на
2.2.1. Это ожидаемо: `pin_memory()` ломался всегда, просто PyTorch до 2.3 его
не вызывал.

## Три уровня починки

Набор применяет их в порядке от самого безопасного к самому полному.

### 1. `PYTORCH_CUDA_ALLOC_CONF=pinned_use_cuda_host_register:True` — попробовать первым

Одна переменная окружения, ничего не патчится. PyTorch вместо `cudaHostAlloc`
берёт обычный `malloc` и вызывает `cudaHostRegister`
(`aten/src/ATen/cuda/CachingHostAllocator.cpp:203-252`).

```bat
set ZLUDA_RX580_HOST_REGISTER=1
```

**Может не сработать.** Путь `hipHostRegister` отличается от `hipHostMalloc`
(`CL_MEM_USE_HOST_PTR` вместо чистого SVM), но если он тоже упрётся в SVM,
то упадёт в `registerPages()` с проверкой
«Host and device pointer dont match with cudaHostRegister». Проверка стоит
нулевых затрат — просто посмотрите на результат диагностики.

### 2. Python-заплатки (включены по умолчанию)

Переписывают те операции, которые выделяют pinned-память внутри себя:

| операция | что происходит |
|---|---|
| `Tensor.item`, `__bool__`, `__float__`, `__int__`, `__index__` | значение копируется на CPU одним элементом — ровно как в PyTorch 2.2.1 |
| `torch.count_nonzero` | переписывается в `(x != 0).sum()`, остаётся на GPU |

Никаких бинарных патчей, работает везде. Цена — одна крошечная копия.
Отключается: `ZLUDA_RX580_NO_PIN_SHIM=1`.

**Не покрывает** вызовы этих операций изнутри C++ (сторонние расширения).

### 3. Подмена `cudaHostAlloc` в памяти процесса (самый полный)

Переписывает слоты IAT в загруженных DLL PyTorch так, чтобы `cudaHostAlloc`
выделял обычную выровненную память через `_aligned_malloc`, а `cudaFreeHost`
освобождал её через `_aligned_free`. Файлы на диске не меняются.

Проверка:

```bat
run_diagnose.bat venv-torch27 --check patch
```

> ⚠️ **Что здесь не проверено.** Механизм рассчитывает, что `torch_cuda.dll`
> импортирует `cudaHostAlloc` из `cudart64_110.dll` через таблицу импорта.
> Скачать wheel PyTorch для Windows в этой среде было нельзя (`download.pytorch.org`
> недоступен), поэтому прямо подтвердить это не удалось. На 66 настоящих
> Windows-бинарниках из wheel `cupy-cuda11x` и `nvidia-cuda-runtime-cu11`
> импорт `cudaHostAlloc` **не нашёлся ни разу** — cupy грузит функции CUDA
> динамически. Поэтому патч не «чинит молча», а сообщает, что нашёл:
> если слотов не найдено, вы увидите явное сообщение и список просмотренных
> модулей. Пришлите этот вывод — и станет понятно, что делать дальше.
>
> `set ZLUDA_RX580_SCAN_ALL=1` — просматривать все загруженные модули, а не только torch.

## Диагностика

```bat
run_diagnose.bat venv --list          :: список проверок
run_diagnose.bat venv --check item    :: одна проверка
run_diagnose.bat venv --patch         :: всё с подменой cudaHostAlloc
```

Каждая проверка выполняется в отдельном процессе, поэтому падение драйвера в
одной не мешает остальным.

| проверка | что делает |
|---|---|
| `env` | версии, файлы в `torch\lib`, адреса `_aligned_malloc`/`_aligned_free` |
| `device` | видна ли карта, имя, объём памяти |
| `matmul` | умножение матриц на GPU, сверка с CPU |
| `item` | `.item()` — выделяет pinned-память с 2.3.0 |
| `pin` | `pin_memory()` — прямой вызов `cudaHostAlloc` |
| `nonzero` | `count_nonzero(...) > 0` — строка из `comfy/samplers.py` |
| `roundtrip` | сверка значений `.item()` и `.cpu()`, целостность данных |
| `shim` | Python-заплатки: значения не должны меняться |
| `patch` | подмена `cudaHostAlloc` и повтор всех проверок памяти |

## Переменные окружения

| переменная | действие |
|---|---|
| `ZLUDA_RX580_DISABLE=1` | выключить набор полностью |
| `ZLUDA_RX580_FORCE=1` | считать, что ZLUDA есть, без проверки имени устройства |
| `ZLUDA_RX580_HOST_REGISTER=1` | уровень 1 — `pinned_use_cuda_host_register` |
| `ZLUDA_RX580_NO_PIN_SHIM=1` | выключить уровень 2 |
| `ZLUDA_RX580_NO_PIN_PATCH=1` | выключить уровень 3 |
| `ZLUDA_RX580_SCAN_ALL=1` | просматривать все модули в поисках слотов IAT |
| `ZLUDA_RX580_HIDE_ROCM=1` | убрать ROCm из окружения (как в форке ComfyUI-Zluda) |

`DISABLE_ADDMM_CUDA_LT=1` ставится автоматически: путь cublasLt в `addmm`
на Windows включён начиная с PyTorch 2.4, а hipBLASLt в HIP SDK 5.7 его не
поддерживает.

## Ручное подключение (без `.pth`)

Если автоактивация через `.pth` не нужна, добавьте первой строкой в `main.py`:

```python
import zluda_rx580.activate  # noqa: F401
```

```bat
python -m zluda_rx580.install_pth --remove
python -m zluda_rx580.install_pth --show
```

## Тесты

```bat
python -m unittest discover -s tests -t . -v
```

Тесты не требуют ни Windows, ни GPU, ни torch. Что они проверяют по-настоящему:

* **PE-парсер** — на синтетическом PE32+ образе, собранном в самом тесте, и
  сверка с `pefile` на 66 настоящих Windows-бинарниках из wheel `cupy-cuda11x`
  и `nvidia-cuda-runtime-cu11` (нужны `pefile` и `ZLRX580_REAL_BIN_DIR`);
* **машинный код заглушек** — байты сверяются с эталоном, а затем **исполняются
  в эмуляторе unicorn**: проверяются коды возврата, записанный указатель,
  аргументы `_aligned_malloc`, поведение при `size == 0` и `pHost == NULL`,
  а также выравнивание стека по 16 байт на момент `call`;
* **Python-заплатки** — против настоящего PyTorch, с временной подменой
  `Tensor.is_cuda`, чтобы исполнить именно ветку для CUDA;
* **хук импорта** — в отдельном интерпретаторе: настройки применяются после
  `import torch` и не применяются при `ZLUDA_RX580_DISABLE=1`.

## Ограничения, о которых стоит знать

* `cufft` / `cufftw` **не подменяются**: в сборке ZLUDA rocm5 их обычно нет.
  Поэтому `torch.stft` / `torch.istft` откатываются на CPU.
* Официально ComfyUI требует PyTorch ≥ 2.7 с 2026-08-08; версии 2.4–2.6 тоже
  могут работать, но форк ComfyUI-Zluda больше их не поддерживает.
* Никакой готовой пары «torch 2.7 + ZLUDA rocm5» в скриптах ComfyUI-Zluda нет:
  там 2.7.0+cu118 идёт только со сборкой ZLUDA под HIP 6. Этот набор сочетает
  2.7+cu118 с rocm5 — и именно поэтому диагностика здесь обязательна.
